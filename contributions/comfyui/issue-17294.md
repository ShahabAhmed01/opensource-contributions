## Root cause

`server.py post_prompt` runs `validate_prompt` → `validate_inputs()`
over `json_data["prompt"]` **in place** before `prompt_queue.put(...)`.
In `validate_inputs()`, the `__value__` unwrap for list widget values
(the wrapper that exists because a bare list in the prompt means a node
link) ended with `inputs[x] = val`, writing the bare value back into the
submitted prompt. Everything downstream therefore stores the unwrapped
form:

- `/history`: `PromptQueue.task_done` stores the queued item tuple
  `(number, prompt_id, prompt, ...)` — `history["prompt"][2]` is the
  mutated prompt dict.
- PNG metadata: the hidden `PROMPT` chunk reads
  `dynprompt.get_original_prompt()`.

When such an image is reopened, `[1, 2, 3]` (an array widget value) is
indistinguishable from a two-element node link, so the array widget
values are lost.

Execution had depended on that mutation: `get_input_data()` read
`dynprompt.get_node(...)['inputs']` with the wrapper already stripped.

## Fix

- `execution.py validate_inputs()`: the `__value__` unwrap now assigns
  to the local `val` only — the prompt is never rewritten (the
  `int()/float()/str()/bool()` coercions are untouched).
- `execution.py get_input_data()`: calls `get_input_info()` first, then
  unwraps `__value__` gated on `input_category in ("required",
  "optional")` — exactly the input set `validate_inputs()` iterates.
  Hidden and undeclared inputs (which validation never visits) are read
  exactly as submitted, so node-facing behaviour is byte-for-byte
  pre-existing; only storage changed. This gate is the result of the
  CodeRabbit review exchange (below).
