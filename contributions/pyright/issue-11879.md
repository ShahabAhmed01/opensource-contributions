## Issue

https://github.com/microsoft/pyright/issues/11879
"Unpack Parameter does not work with functools.partial"

Opened 2026-10-14T20:01:07Z, labeled `bug`, 0 comments, no assignee.
Reporter repro (PyGObject idle_add):

```python
from typing import Callable, TypeVarTuple
from functools import partial
_TestTs = TypeVarTuple("_TestTs")

def idle_add(function: Callable[[*_TestTs], bool], *user_data: *_TestTs) -> int: ...

def test(a: int) -> bool: ...
partial(idle_add, test, "a")  # spurious Argument-of-type error at creation
```

The equivalent direct call `idle_add(test, 1)` is accepted by pyright,
but going through `functools.partial` errors with
`Argument of type "Literal['a']" cannot be assigned to parameter "user_data"
of type "*_DataTs@_test"`, because the constructor transform in
`constructorTransform.ts` validated each positional argument bound to an
unpacked-TypeVarTuple `*args` parameter directly against the *unsolved*
TypeVarTuple.

Availability re-verified immediately before the commit and immediately
before the PR via `/issues/11879/timeline` (0 cross-referenced events =
no competing PR; the search API is unusable with this token — no `search`

## Fix

`packages/pyright-internal/src/analyzer/constructorTransform.ts`
(+197 net): arguments targeting the variadic parameter are deferred
during argument processing (`argIndex >= paramListDetails.argsIndex` —
must include args landing exactly ON the variadic param index); after
the loop, the TypeVarTuple is solved from the non-variadic constraints:

- solvable → bound args validated as a PREFIX of the solved tuple via
  per-entry `assignType` with a throwaway tracker; parameter type trimmed
  to the remainder (`replaceVariadicParamType` via `FunctionType.specialize`);
  empty remainder → `makeTupleObject(evaluator, [], /* isUnpacked */ true)`
  rather than param removal (solving unpacks the var into Simple params).
- partially solvable → DEFERRED: solve `Ts := (bound..., *Ts2)` with a
  fresh TypeVarTuple named `${name}2` created via
  `TypeVarType.createInstance` (instance form REQUIRED — instantiable
  form breaks call-time solving, printing `type[_DataTs2]`), scoped to
  the original's `scopeId`.
- unsolvable (no constraints) → parameter left unchanged.

Also strips the inherited `FunctionTypeFlags.GradualCallableForm` from
the synthesized `__call__` so `reveal_type` doesn't print `(…) -> int`.
