# Project notes — pytest-dev/pytest

Last verified: 2026-10-20
## Facts

- Python's de-facto standard test framework. Python 3.10+, MIT, 14,616
  stars / 3,523 forks (live 2026-10-20; cloned 2015-06-15; ~874 open
  issues+PRs). One of the highest-traffic repos in the Python
  ecosystem: every failed collection lands on hundreds of thousands of
  CI runs.
- Default branch `main`; PRs target `main`. Test suite in `testing/`,
  runtime in `src/_pytest/` (the historical `src` layout means
  `pip install -e .` is mandatory — running `pytest` from the checkout
  root without it picks up the repo-local `pytest`-less environment).
- Changelog entries are `changelog/<issue>.<type>.rst` files
  (`breaking|deprecation|feature|improvement|bugfix|vendor|doc|
  packaging|contrib|misc`) with a pre-commit hook policing the naming;
  `AUTHORS` gains a line per first-time contributor.
- Version is date-setuptools-scm'd from git; a shallow clone needs
  `SETUPTOOLS_SCM_PRETEND_VERSION=<x.p.y.dev0>` to build/install.

## AI/LLM-assisted contributions policy (CONTRIBUTING.rst, the binding contract)

- **Welcome:** contributions from all developers including those using
  AI/LLM tools as part of the workflow; pytest-core itself uses them
  daily (Anthropic's open-source grant is cited in the section).
- **Required:** the submitting human understands the change, stands
  behind it, and can engage substantively with review feedback — "if a
  reviewer asks questions, they expect to interact with someone who can
  engage, not an automated loop replaying prompts".
- **Not accepted:** *purely agentic* output ("entirely generated by AI
  agents, with no meaningful human review, understanding, or oversight"
  → closed), unattended bulk changes, and drive-bys against an issue the
  author never engaged with. The section names "clankers" signatures —
  generic commit prose, confidently-wrong diffs, inability to answer a
  simple "why" — and says the team now *closes and bans with prejudice*
  when those patterns show up.
- **Attribution:** `Co-authored-by` trailers crediting AI agents are
  encouraged ("not required, but helps reviewers set expectations").
- **Our standing interpretation** (prior sessions read this policy as
  "drive-by agentic PRs rejected" and hard-gated pytest): the gate is on
  accountability, not on tooling. Any pytest lane here must (a) target a
  real, measured issue and engage with it, (b) disclose AI tooling in
  the PR body, (c) keep one PR open at a time, (d) answer review from
  the account — the account holder is the responsible human, and our
  automation never replies on their behalf without their direction.

## Development / validation commands (verified 2026-10-20)

```bash
SETUPTOOLS_SCM_PRETEND_VERSION=9.1.2.dev0 pip install -e .   # shallow checkout
SETUPTOOLS_SCM_PRETEND_VERSION=9.1.2.dev0 python -m pytest \
    testing/test_collection.py testing/test_main.py          # the collection lane
.venv/bin/ruff check src/_pytest/main.py testing/test_collection.py
.venv/bin/ruff format --check src/_pytest/main.py testing/test_collection.py
.venv/bin/mypy src/_pytest/main.py testing/test_collection.py  # repo config in pyproject
coverage run -m pytest testing/test_collection.py               # codecov/patch pre-flight
```

- The pinned pre-commit versions rule both statics: ruff v0.17.1, mypy
  v2.4.0 (hooks over `^(src/|testing/|scripts/)`), zizmor, codespell,
  blacken-docs, pyproject-fmt; `pyright` is manual/stages:[manual].
- `codecov.yml` (no dot at repo root) sets **patch target 100%** and
  project checks off; `code: ignore` unset — so any PR whose added
  lines are not fully executed by CI fails `codecov/patch`. Run the
  touched files under coverage before pushing.
- Full CI is a ~34-check matrix (30 build jobs + check + codecov/patch +
  Changelog entry + package) plus commit statuses `pre-commit.ci - pr`
  and `docs/readthedocs.org:pytest`. It completes in ~15 minutes, and
  coverage uploads from the slowest jobs can re-run `codecov/patch`
  *after* its first conclusion — judge patch coverage only once every
  enabled job has uploaded.

## Why this project was selected (2026-10-20 research)

- **Scale + acceptance:** 14,616 stars; outside contributions merge
  routinely (of the six most recently merged PRs examined 2026-10-20 —
  #15225 autoupdate, #15212/#15211 dependabot, #15192, #15179, #15128 —
  #15192 is an outside author's build/docs fix merged 2026-10-17 and
  #15128/#15225/ci PRs show the team's own maintenance cadence; the
  repo's governance is by pytest-core including RonnyPfannschmidt).
  Merge acceptance is review-gated, not bot-gated: 34 green checks put a
  PR in the review queue, reviews decide.
- **Issue quality:** collector-performance reports arrive
  measurement-first (`#15221`: profiled timings, call counts, a
  workaround's deltas, an items-identical claim on 9,608 and 38,514
  nodes) — these are reproducible acceptance contracts, and picking one
  fresh (filed the previous day, 0 comments, no competing PR) is the
  way to contribute without contesting a line.
- **Verifiable locally with no network beyond the API:** pytest's own
  suite runs offline; the perf repro is file-system work; statics pin
  exactly like pre-commit.
- **Why not before:** prior sessions treated pytest as hard-gated
  under the AI policy. The 2026-10-20 read of `CONTRIBUTING.rst`'s
  policy section (above) says the gate is accountability, not tooling —
  the reservation for this repo was made only after re-reading that
  section, and the PR discloses tooling on day one.

## Pitfalls learned

- The collection contract "files given directly multiple times on the
  command line should not be deduplicated" is implemented by *skipping
  the collection cache for that call*, which is invisible until you
  touch parent-level caching: any reuse must carve out **repeated**
  file arguments or it changes `--keepduplicates` and `::`-part
  semantics. Two of four tests pin that carve-out.
- `codecov/patch` fails loudly mid-rollup (76.47% with jobs in flight
  → success on its re-run once uploads complete). Before reporting a
  coverage failure, run the touched files under coverage locally and
  compare the missed-line ranges against the diff.
- Shallow clones can't produce a setuptools-scm version; work around
  with `SETUPTOOLS_SCM_PRETEND_VERSION` for local runs, and never let a
  venv's `uv.lock`-style churn (nothing equivalent here) enter commits.
- The changelog pre-commit hook is strict about filenames
  (`####.<type>`), and `changelog/15221.improvement.rst` is why "check
  changelog naming" is part of CI, not a guess.
- PRs from forks are `mergeable_state: blocked` until the protection
  gate clears — that is normal here (no first-time workflow-approval
  dance, unlike some repos; `pre-commit.ci` and the matrix ran on the
  first push unprompted).

## Contribution history

### #15221 — explicit file arguments re-collect the parent level per argument (**PR OPEN, CI green** as PR #15228, 2026-10-20)

- Branch: `contrib/issue-15221-collect-parent-cache-b6ebdc41`; PR:
  https://github.com/pytest-dev/pytest/pull/15228 (base `main` @
  `49ea4d0`), closes https://github.com/pytest-dev/pytest/issues/15221.
- Full record: [`contributions/pytest/issue-15221.md`](../contributions/pytest/issue-15221.md).
- Fix: `perform_collect` precomputes the set of file-argument paths
  that occur more than once among initial arguments; `Session.collect`
  fresh-collects those (dedup contract intact) and reuses the level's
  cached report for once-only file arguments; failed cached reports are
  still re-collected.
- Validation: 143+103+68+733 local test files green (see record for the
  exact counts), perf repro 2.31s → 0.39s at 100 file arguments, ruff
  0.17.1 + mypy 2.4.0 clean on the changed files, coverage run shows
  every added line executed; CI 34/34 check-runs success + both commit
  statuses at review time. AI assistance disclosed in the PR body per
  `CONTRIBUTING.rst`; body revised once post-publication (stale local
  statics replaced, disclosure added) without moving the head.

### #3649 — `--pdb` should not enter the debugger for a syntax error (**PR OPEN, CI running** as PR #15239, 2026-10-21)

- Branch: `fix/3649-pdb-syntax-error`; PR:
  https://github.com/pytest-dev/pytest/pull/15239 (base `main` @
  `c9bf1ed`), closes https://github.com/pytest-dev/pytest/issues/3649.
- Full record: [`contributions/pytest/issue-3649.md`](../contributions/pytest/issue-3649.md).
- Fix: `importtestmodule` re-raises a `SyntaxError` as a `CollectError`
  that keeps the original `SyntaxError` as its `__cause__`;
  `collect_one_node` now recognises that case and skips
  `pytest_exception_interact`, so `--pdb` no longer opens the debugger
  on the `raise` statement. The error is still reported with its full
  traceback, and every other collection error still opens the debugger.
- Why this issue: an explicit maintainer green light in the thread
  (asottile, 2018-10-19 — "no no, this is definitely worth fixing"),
  open since 2018, unclaimed (no linked or competing PR at publication),
  and a crisp, single-cause bug with an unambiguous expected behaviour.
- Validation: `testing/` 4698 passed / 47 skipped / 13 xfailed,
  `testing/test_debugging.py` 54 passed / 1 skipped, ruff 0.17.1 + mypy
  2.4.0 clean on the changed files, and a local coverage run with the
  repo's own config (`patch = ["subprocess"]`) shows every added line
  executed — pytest's `codecov/patch` target is 100% of the diff.
- Repo facts learned on this lane (2026-10-21): this account is
  **blocked from commenting on other users' issues** in pytest-dev/pytest
  (the API answers "User is blocked") while commenting on its own pull
  requests works — so root-cause analyses have to go into the PR
  description, and an issue-comment-first workflow is not available
  here. Pull-request creation, however, is allowed.
